# 2027 東北滑雪・極致粉雪與冬奧入瀨秘境行

16 天青森・岩手滑雪行程的單頁網站。`index.html` 是**自帶資料的完整單檔 HTML** ——
直接用瀏覽器開啟就能看，不需要伺服器、不需要網路（雪道圖除外）。

## 設計系統 — Midnight & Champagne（墨黑 × 香檳金）

| 項目 | 選用 | 理由 |
| --- | --- | --- |
| 主色 | 墨黑 `#0B0B0D` × 香檳金 `#C9AB76` | 雪場夜景與深色底最搭，金色在近黑上最貴氣 |
| 標題字 | Bodoni Moda（Didone 高對比襯線） | Vogue／Harper's Bazaar 的時尚雜誌語彙 |
| 中文字 | 系統明體（Songti TC／Hiragino Mincho／Yu Mincho） | 不下載 CJK 字檔，手機流量與離線都不吃虧 |
| 版面 | 髮絲級金線分隔、無圓角、大量留白、超大 Bodoni 數字 | 雜誌排版而非 App 排版 |
| 動態 | 進場淡入上升、頂部閱讀進度、金線 hover 展開、底噪顆粒 | 現行網頁流行元素，但都克制在「質感」而非「花俏」 |

### 晝夜雙主題

右上角 `MIDNIGHT ⇄ BONE` 切換：

- **Midnight（墨黑）** — 預設。這是品牌識別，首次造訪一律走這套，不跟隨系統設定。
- **Bone（骨白）** — 暖紙白底、深金，雪地大太陽下看手機用這套。

選擇存在 `localStorage`（key：`sb2027.theme.v1`），下次開自動沿用。

兩套主題的正文、統計數字與小字標籤全部實測 **≥ 4.5:1** 對比（WCAG AA）。

> 字體從 Google Fonts 載入。**沒有網路時 Bodoni 不會載入**，中英文都會退回系統襯線字，版面不會壞，只是少了 Didone 的味道 —— 這是刻意的取捨，避免為了字體塞幾 MB 進頁面。

## 頁面功能

### 🏔️ 場地資訊卡（雪場／景點／場館）

13 張折疊卡，**平常收起，點標題才展開**。

- **統計列** — 雪場顯示 `頂部高度 / 雪道數 / 最長滑道 / 開幕日 / 交通`；
  景點與場館改顯示 `開館時間 / 休館日 / 門票 / 建議停留 / 交通`。
- **連結列** — `官網`、`運行狀態`、`Snow-Forecast 預估雪況`、`官方雪道導覽`、`Google 地圖`。
- **地圖圖片** — 直接顯示在卡內，**展開時才開始載入**（未展開不發出任何圖片請求）。
  載入失敗會依序：改試備用雪道圖 → 顯示失敗提示與「重新載入」按鈕，
  不會留下破圖。5 座雪場皆有官方雪道圖；景點與場館以 Google 地圖連結替代。
- 上方可依 `雪場／場館／景點／市場／祭典` 篩選；每日行程中的場地標籤點了會跳到對應卡片並自動展開。

### ❄️ 未來 3 天雪況（Open-Meteo，即時）

5 張雪場卡展開時才向 [Open-Meteo](https://open-meteo.com/) 抓未來 3 天，
**不隨頁面一起發佈，所以永遠是最新的**。每天顯示新雪 cm、最高／最低氣溫、最大陣風。

**陣風 ≥ 40 km/h** 的日子整格變色並標「⚠ 高空吊椅易停駛」。
（八甲田纜車本身的停駛門檻是 25 m/s ≈ 90 km/h，寫在該卡的注意事項裡，兩者不衝突。）

- 只在第一次展開時抓，之後用記憶體快取，重複開合不會重打 API
- 9 秒逾時；失敗、HTTP 錯誤、格式非預期、離線都會顯示原因與「重新載入」，並指向 Snow-Forecast
- 欄位是 `null` 時顯示「—」，不會出現 `NaN`，也不會誤判為無風
- 以雪場**山頂高度**當 `elevation` 參數送出，讓模型降尺度到真正的滑雪高度

> **座標的誠實說明**：八甲田的座標已查證；其餘 4 座是依地址與所在山體**估算**的
> （建置環境擋掉了 Wikipedia／Nominatim／Mapion，無法在此查證），誤差約數公里。
> 在 ~5 km 的預報網格上影響不大，但每張卡都把座標印出來並附地圖連結，
> **點一下就知道圖釘有沒有落在雪場上**；覆核清單也有對應項目。
> 要修正就改 `itinerary.json` 裡 `venues[].forecast` 的 `lat` / `lon`。

### ✅ 出發前覆核清單

4 組共 35 項勾選框：**訂位與預約 / 時刻表公布 / 營業狀況 / 行李與雪具規定**。

- 勾選狀態存在瀏覽器的 `localStorage`（key：`sb2027.checklist.v1`）。
- 換裝置或清除瀏覽資料後需重新勾選；瀏覽器停用本機儲存時頁面仍可正常使用，只是不會保存。
- 頂部有完成度圓環與各組計數，另有「清除全部勾選」。

### 📍 今日視圖

頁面頂端的面板會依照**這台裝置的今天**自動切換三種狀態：

| 狀態 | 顯示 |
| --- | --- |
| 出發前 | 倒數天數 ＋ 覆核與打包各還剩幾項 ＋ 兩個捷徑 |
| 旅行中 | 今天是第幾天、當日標題、住宿、交通摘要、相關場地、跳到完整行程與緊急聯絡 |
| 結束後 | 收尾訊息與回顧連結 |

旅行中當天也會在日期列以金線標示。

**預覽任一天**：網址加上 `?today=YYYY-MM-DD`，例如
[`?today=2027-02-13`](https://jonwenjen.github.io/2027_SB_Aomori/?today=2027-02-13)。
測試也是靠這個參數跑的。

### 🎒 裝備打包清單

與覆核清單同一個元件、**不同的儲存 key**（`sb2027.packing.v1`），兩份進度互不影響。
6 組共 49 項，內容綁這趟行程：八甲田的雪崩三寶、奧入瀨的防滑冰爪、
硫磺泉會讓銀飾變黑、台日同為 Type A 插頭不需轉接頭。

### 🚨 緊急聯絡與求救

**這一段刻意不做進場動畫。** 其他區塊可以淡入，這一段不行 ——
需要它的時候，內容必須在頁面畫出來的瞬間就看得到，不能卡在動畫上。
另外全頁有一道 4 秒的保險：任何還沒顯示的區塊一律強制顯示。

- 13 組號碼做成 `tel:` 一鍵撥號，每列至少 44px 高（戴手套、手冷時也點得到）
- **撥不通的號碼不做成連結** —— 外交部 0800 免付費線在日本撥不通，
  所以它是灰色純文字加 ⚠️ 說明，不會讓人在緊急時點了一支空號
- 雪崩夥伴救援與迷途受困兩套程序、11 句日文急救短句（點一下整句選取，直接給對方看）
- 個人欄位（保單、緊急聯絡人、血型過敏）**只寫進這台裝置的 localStorage**，
  不上傳、不進 GitHub、不進 repo

所有號碼都逐一對照發證單位官網查證，沒有一支是憑記憶寫的。

### 🗓️ 每日行程・🛡️ 應急備案

16 天逐日動線、交通時刻與 960 筆在地推薦（6 類各 10 選，以食べログ高分榜為主），
以及 4 組天候與交通應變方案。

## 發佈與同步流程（全雲端）

```
在 Claude Code 修改 itinerary.json / template.html
        ↓
python3 build.py                 ← 打包成完整單檔 index.html
        ↓
git commit && git push           ← 推上 GitHub repo: 2027_SB_Aomori
        ↓
GitHub Actions 驗證 index.html 與資料一致
```

### 日常操作

```bash
# 1. 改資料或版面之後重新打包
python3 build.py

# 2. 確認 index.html 沒有跟資料脫節（CI 也跑這一行）
python3 build.py --check

# 3. 本機預覽（或直接用瀏覽器開 index.html）
python3 -m http.server 8000
```

`build.py` 會檢查 `itinerary.json` 必要欄位是否齊全，並把 JSON 內嵌進
`<script type="application/json">`（`<`、`>`、U+2028/9 皆已轉義）。
若打包步驟被跳過、佔位字串仍在，頁面會自動退回 `fetch('./itinerary.json')`，
所以 `template.html` 單獨放在同目錄也能運作。

### GitHub Actions

`.github/workflows/build-site.yml` 在每次 push 與 PR 時執行 `build.py --check`。
**忘記重新打包就會讓 CI 變紅**，避免 `index.html` 與 `itinerary.json` 不同步。

- 雪場數據取自各雪場官方冬季頁與日本滑雪資料庫（SURF&SNOW／楽天トラベル／スノーパラダイス東北）。
- 景點與場館數據取自各館官方網站。
- **開幕日與營業期間為最近一個已公布雪季的日期**。2026/27 雪季行事曆尚未公布，
  請以頁面上的「出發前覆核清單」逐項重新確認 —— 清單就是為此而存在。
- 資料覆核日記於頁尾。
